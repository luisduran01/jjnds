# Corner Club 3D Club Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace disconnected 2D routes with a 3D club hub whose career, quick-fight and bag-training stations share the current boxing combat scene.

**Architecture:** `GameManager` holds an explicit fight context consumed by `boxing/main.gd`. A reusable procedural 3D gym hub owns navigation stations. A separate 3D heavy-bag scene reuses `Fighter` hit events and evaluates punch sequences.

**Tech Stack:** Godot 4.7, GDScript, Node3D/Area3D/RigidBody3D, Label3D, existing `Fighter` and combat tests.

**Spec:** `docs/superpowers/specs/2026-09-21-corner-club-3d-club-flow-design.md`

## Global Constraints

- Keep `boxing/main.tscn` as the sole fight gameplay destination.
- Keep the existing combat suite green before and after each task.
- Use procedural Godot geometry/materials; do not introduce a premade simulation asset.
- Retain 2D overlays only for in-match readability, never as the primary menu flow.

## Review Focus

- Missing career save opens valid 3D new-career flow rather than a null-profile fight.
- Direct test launch of `boxing/main.tscn` retains default profiles.
- Career context persists result while quick-fight context does not mutate it.
- Out-of-order, stale or non-contact bag punches never advance the combination.
- No button, results route or pre-fight route reaches `scenes/arena/fight_3d.tscn`.
